# Сравнение DAI на Eltex MES1428 и CIT SB210

Степанов Р. В. и Хорт М. Ю., группа КС-25-03. Работа NET25-065 / NET-092.

На каждом коммутаторе провели замеры с выключенным и включённым Dynamic ARP Inspection (DAI). Проверяли три вещи: меняется ли MAC шлюза в ARP-таблице тестового компьютера, проходят ли его запросы к шлюзу через Kali и сколько запросов остаётся без ответа. Cisco Catalyst 2960 выдавал адреса по DHCP и служил тестовым шлюзом.

## Где лежат файлы

| Папка или файл | Что внутри |
| --- | --- |
| [`scripts/`](scripts/) | Три Python-скрипта для разбора сохранённых данных. А так же скрпиты для атаки и замеров|
| [`logs/victim_logs/`](logs/victim_logs/) | Журналы тестового компьютера. В них записаны MAC шлюза, результаты ping и признаки подмены. |
| [`logs/kali_logs/`](logs/kali_logs/) | Журналы запусков на Kali с метками прогонов. |
| [`logs/cisco2960.log`](logs/cisco2960.log), [`logs/pusty.log`](logs/pusty.log) | Сессии PuTTY с настройками Cisco. Оба файла относятся к Cisco. |
| [`csv/results.csv`](csv/results.csv) | Исходные результаты замеров на тестовом компьютере. Один номер прогона может встречаться несколько раз. |
| [`csv/kali_intercept.csv`](csv/kali_intercept.csv) | Исходные счётчики кадров и пакетов, полученные на Kali. |

| [`csv/pcap_metrics.csv`](csv/pcap_metrics.csv) | Пересчитанные счётчики ARP и ICMP по каждому захвату. |

Например, `eltex_off_01.pcap` — захват прогона № 1 на Eltex с выключенным DAI, а `cit_on_03.pcap` — прогона № 3 на CIT с включённым DAI. Два захвата с меткой `pilot` относятся к пробным прогонам. В `cit_on_05.pcap` есть только заголовок файла. По нему нельзя судить о наличии или отсутствии перенаправления. Скриншоты находятся в исходном комплекте `Publication2-try1`.

## Скрипты, использованные на стенде

| Скрипт | Что делал |
| --- | --- |
| `trial.sh` | Работал на тестовом компьютере. Перед замером очищал кэш ARP, проверял связь со шлюзом и записывал его MAC. Во время замера отправлял 100 запросов ping и фиксировал два наблюдения MAC шлюза. Записывал признак подмены и потери в журнал и `results.csv`. |
| `kali_attack.sh` | Сценарий для прогона на Kali без записи PCAP. Сохраняет журнал Bettercap и по его сообщениям отмечает, была ли рассылка ARP. Отправку кадров для основного анализа проверяли по захватам. |
| `kali_intercept.sh` | Сохранял трафик с Kali в PCAP и записывал счётчики в `kali_intercept.csv`. Его исходный счётчик входящего ICMP учитывал также сообщения об ошибках. Поэтому запросы тестового компьютера к шлюзу пересчитали отдельно по PCAP. |

## Как работают скрипты анализа

- [`analyze_experiment.py`](scripts/analyze_experiment.py) читает CSV и сохранённые захваты. Если поле `victim_ip` разорвано переносом строки, скрипт собирает запись обратно и отмечает исправление в `csv_repairs.csv`. Затем он находит в PCAP запросы ping к шлюзу, которые пришли на MAC Kali. Чтобы подтвердить пересылку, ищет тот же запрос в исходящем кадре к шлюзу по идентификатору, номеру и содержимому ICMP. Основные файлы результата — `pcap_metrics.csv`, `forwarding_pairs.csv`, `trials_last_record.csv` и `summary.json`.
- [`audit_details.py`](scripts/audit_details.py) сверяет признаки подмены и потери из CSV с журналами тестового компьютера. В `log_checks.csv` указано, сколько попыток было под каждым номером и совпадают ли записи.
- [`extra_stats.py`](scripts/extra_stats.py) сравнивает время CSV с временем окончания захвата. Это помогает заметить случаи, когда под одним номером сохранились разные попытки. Скрипт записывает сверку в `capture_time_alignment.csv` и рассчитывает сводку по пригодным захватам в `traffic_stats.json`.

Повторный запуск мог оставить несколько строк в CSV под одной меткой и заменить файл захвата. Поэтому при проверке отдельной попытки смотрите одновременно на метку, время и журнал. Для проверки пересылки откройте нужный PCAP в Wireshark и найдите номера входящего и исходящего кадров из `forwarding_pairs.csv`.

## Как пересчитать результаты

Из корня репозитория выполните по порядку. Достаточно Python 3, без дополнительных пакетов.

```text
python scripts/analyze_experiment.py
python scripts/audit_details.py
python scripts/extra_stats.py
```

Результаты появятся в `analysis/derived/`. Скрипты работают с сохранёнными файлами, исходные CSV, журналы и захваты не меняют.
